Champ Social – Planning des publications

Période du 1er septembre 2026 au 29 janvier 2027. Les dates Édition sont des contraintes prioritaires ; les publications récurrentes sont placées sur des créneaux hors dates Édition.

Lecture seule

Règles appliquées

  • Les dates Édition déjà stockées, à partir du 1er septembre 2026, sont conservées.
  • Aucune publication récurrente n'est placée sur une date Édition.
  • Une journée hors Édition reçoit au maximum 2 promotions récurrentes.
  • Une même journée ne croise pas deux promotions destinées au même public-cible.
  • Une même journée ne croise pas deux publications du même canal, pour éviter deux Mailjet ou deux LinkedIn le même jour.
  • Les formations traditionnelles sont plafonnées à 20 publications ; l'évaluation ESSMS à 30 publications.

Ces règles ont servi au calcul initial. Les modifications faites ici ne sont pas contrôlées automatiquement : à vous de rester cohérent avec elles.

Mode d'emploi

Tout le monde peut consulter, filtrer, exporter et ajouter les publications à son agenda.

Un clic sur une publication ouvre sa fiche : statuts cochables directement, date, heure et sujet modifiables. Le code de modification n'est demandé qu'une fois par appareil, avec votre nom — ensuite les changements se font à la volée.

Chaque changement indique qui l'a fait : le nom apparaît sur la fiche de la publication et dans le journal, en bas de page, y compris pour les membres qui ne font que consulter.

Publication manuelle (secours, sans jeton)

Vos modifications sont d'abord enregistrées dans votre navigateur. Pour que les autres membres les voient, il faut déposer le fichier de données dans le dépôt GitHub — la même manipulation que pour la page elle-même.

  1. Cliquez sur Télécharger le fichier de données ci-dessous : votre navigateur enregistre data/planning.json.
  2. Ouvrez la page de dépôt du dépôt GitHub.
  3. Glissez data/planning.json dans la zone de dépôt, puis cliquez sur Commit changes.
  4. Une minute plus tard, tous les membres voient la nouvelle version en rechargeant la page.

Le fichier planning.ics est facultatif : déposez-le au même endroit si vous voulez que les agendas abonnés reflètent les dernières modifications.

Publication automatique (jeton GitHub)

Avec un jeton d'écriture, la page publie elle-même chaque modification et le dépôt manuel devient inutile.

Le jeton reste dans votre navigateur (il n'est jamais écrit dans la page publiée). Utilisez un jeton « fine-grained » limité à ce dépôt, avec la permission Contents : Read and write. Les lecteurs n'ont besoin d'aucun jeton si le dépôt est public.
